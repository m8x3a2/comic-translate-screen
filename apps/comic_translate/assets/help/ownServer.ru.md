
# Промпт для настройки «Своего сервера» в Comic Translate Screen

Скопируй этот документ в чат с нейросетью и дополни его документацией своего поставщика. Удали из примеров реальные ключи, токены, приватные сообщения и изображения. Введи ключ только в поле «Ключ API» в приложении.

## Задача для нейросети

Помоги мне настроить «Настройки → Переводчик → Свой сервер» в Comic Translate Screen по документации моего API. Используй ограничения приложения ниже. Сначала выясни, нужны ли мне текстовый чат и перевод, каталог моделей, сведения о ключе, OCR с картинками или OCR и перевод одним запросом. Если данных недостаточно, задай короткие вопросы. Не проси настоящий ключ. Не угадывай путь, модель, схему авторизации или поля ответа.

Для настройки я могу предоставить следующие материалы.

- Название сервиса и ссылку на документацию, включая базовый URL и примеры запросов.
- Идентификатор нужной модели и сведения о поддержке изображений. Укажу, если сервер умеет выбирать модель сам.
- Примеры HTTP-статуса и JSON для нужных операций, включая тело ошибки. Вместо секретов использую `<REDACTED>`.
- Если уже пробовал настроить подключение, дам обезличенные «Логи» тестового чата и результат проверки вставленного JSON.

Ответь по шагам. Сначала перечисли точные значения полей профиля и объясни, какие можно оставить по умолчанию. Затем для каждой из трёх операций ниже напиши «штатный запрос», «полный запрос из шаблона» или «операция не нужна / API не поддерживает». Если нужен шаблон, дай отдельно блок HTTP-запроса и блок JSON для «Правила разбора ответа». В конце предложи минимальный тест и покажи, как по его результату понять, какое поле менять. Если протокол не укладывается в редактор, объясни, какая именно часть требует совместимого сервера-посредника или доработки приложения.

## Что вводить в профиль

1. Создай профиль и дай ему понятное имя. В «Адрес API» вводи базовый URL с протоколом и портом, если он указан. Путь операции приложение добавит к базовому URL. Например, база `http://localhost:1234/v1` и путь `chat/completions` дают `http://localhost:1234/v1/chat/completions`. Для сервера с базой без `/v1` оставь адрес как в документации. Суффикс нужен только там, где он указан в API. Не вставляй полный URL запроса в «Адрес API», если в нём уже есть путь самой операции.
2. Введи ключ в поле «Ключ API» и выбери активный ключ профиля. Для локального сервера ключ можно оставить пустым, если сервер его не требует. Перед штатным запуском подключения к облачному адресу приложение проверяет, что ключ сохранён. В шаблоне используй переменную `{{api_key}}` в заголовке. Она подставляет активный ключ. При пустом ключе заголовок с этой переменной пропускается.
3. В «Модель» укажи точный идентификатор из каталога API. Используй «Загрузить модели» или ручной ввод. Поле можно оставить пустым, если сервер сам выбирает модель при отсутствии `model`. OCR требует явно выбранную модель с поддержкой изображений. В «Настройки → Распознавание» можно выбрать тот же профиль и отдельно задать модель OCR.
4. Если сервис совместим со штатными запросами, оставь «Настройки профиля». Для небольших отличий можно изменить пути и дополнительные поля JSON в параметрах совместимости. `null` в дополнительных полях удаляет поле из штатного запроса. `model`, `messages` и `stream` зарезервированы в этом режиме. Меняй лимит токенов только если документация требует `max_tokens`, `max_completion_tokens` или отсутствие лимита.
5. Если отличается метод, авторизация, структура тела или ответа, создай именованный шаблон. Включай полный запрос отдельно для нужной операции. Шаблон хранит структуру запросов, а адрес, модель и ключ берутся из профиля. Если шаблон выбран в нескольких профилях, его правки применяются ко всем этим подключениям.

## 1. Чат, перевод и сетевой OCR

Штатно используется `POST chat/completions`. Обычный текстовый чат, перевод и OCR через профиль пользуются одной операцией HTTP. Тестовый чат отправляет переписку. Перевод и OCR добавляют инструкции приложения и данные рамок. Изображения в совместимом чате передаются в массиве `content` как элементы `type: "image_url"` с вложенным `image_url.url` и `data:…;base64,…`. Выбирай модель, которая принимает такой формат, если нужен OCR или чат с изображениями.

В редакторе полный HTTP-запрос выглядит так.

```http
POST chat/completions
Authorization: Bearer {{api_key}}
Content-Type: application/json

{
  "model": {{model}},
  "messages": {{messages}},
  "temperature": {{temperature}},
  "max_completion_tokens": {{token_limit}}
}
```

Пустая строка между заголовками и телом обязательна, когда есть тело. В JSON этой операции доступны `{{model}}`, `{{messages}}`, `{{temperature}}`, `{{max_completion_tokens}}`, `{{max_tokens}}`, `{{token_limit}}`, `{{payload}}`. Вставляй переменную как целое значение без кавычек. `{{payload}}` вставляет стандартное тело целиком. В примере поменяй имя поля лимита или убери его по документации. Если переменная поля объекта недоступна, поле пропускается. В полном запросе дополнительные параметры тела задавай в самом шаблоне.

Например, при отправке одного короткого сообщения `{{messages}}` может подставить массив `[{"role":"user","content":"Ответь OK"}]`. Для OCR вместо простой строки в `content` могут прийти текстовый элемент и один или несколько элементов с изображениями. Оставь `{{messages}}` динамическим, иначе текст пользователя, инструкции или рамки не попадут в запрос.

Для штатного ответа используй следующие правила разбора.

```json
{
  "text": "choices[0].message.content",
  "finish": "choices[0].finish_reason",
  "usage": "usage",
  "error": "error.message"
}
```

`text` обязателен. Он должен вести к непустой строке или массиву объектов с полем `text`. `finish`, `usage` и `error` необязательны. Этот JSON можно проверить локально с HTTP-статусом 200.

```json
{"choices":[{"message":{"content":"OK"},"finish_reason":"stop"}]}
```

Это внешний JSON ответа сервера. Текст, извлечённый по `text`, у перевода должен содержать JSON с исходными ключами рамок, например `{"block_0":"Привет","block_1":"Пока"}`. Ключи могут быть другими при переводе нескольких страниц сразу. Сохраняй ровно те ключи, которые пришли в запросе. OCR ждёт строки вроде `[01-001] Hello`, а в совместном режиме — `[01-001] Hello --> Привет`. Номера рамок тоже берутся из запроса. Дополнительные промпты могут менять стиль и терминологию. Формат и идентификаторы рамок должны сохраниться. Проверяй извлечённый текст отдельно в «Редакторе промпта».

## 2. Каталог моделей

Штатный запрос `GET models`. Если сервер не даёт каталог, используй ручной ввод идентификатора модели. Ниже показан полный запрос.

```http
GET models
Authorization: Bearer {{api_key}}
```

```json
{
  "items": "data",
  "id": "id",
  "name": "name",
  "vision": "architecture.input_modalities",
  "error": "error.message"
}
```

`items` обязателен и ведёт к массиву. `id` обязателен и задаётся относительно элемента массива. `name` и `vision` необязательны и тоже считаются от элемента. `vision` отмечает модель, если значение равно `true` или массив содержит `"image"`. Оставь это правило только если оно подходит к ответу сервиса. Ниже показан пример ответа.

```json
{"data":[{"id":"demo/vision","name":"Demo Vision","architecture":{"input_modalities":["text","image"]}}]}
```

## 3. Сведения о ключе

У произвольного сервера нет универсального URL для лимита или баланса. Укажи запрос только если поставщик его документирует. Можно использовать относительный GET-путь и поля ответа в параметрах совместимости либо настроить полный HTTP-запрос. Ниже условный пример. Используй его, только если документация подтверждает путь и структуру.

```http
GET usage/key
Authorization: Bearer {{api_key}}
```

```json
{
  "fields": {
    "Остаток": "data.balance",
    "Единица": "data.unit"
  },
  "error": "error.message"
}
```

`fields` обязателен. Слева подпись для интерфейса, справа путь к строке, числу или булеву значению. Запрашивай только необходимые сведения. Не добавляй путь к значению ключа, токену или паролю. Этот JSON можно подставить для проверки.

```json
{"data":{"balance":12.5,"unit":"credits"}}
```

## Потоковый ответ SSE

Поток должен завершаться событием `data: [DONE]` или сигналом, указанным в `done_data` или `done_event`. Если соединение закроется раньше, чат сохранит полученный текст с пометкой «Ответ незавершён».

Для OpenRouter и OpenAI-совместимых подключений в настройках переводчика можно включить «Потоковый ответ (SSE)». Параметр «Своего сервера» сохраняется в выбранном профиле. Если активен полный HTTP-запрос «Чат и перевод», формат потока определяется его правилами.

В полном запросе чата укажи `"stream": {{stream}}` в теле или используй `{{payload}}`. При формате SSE переменная `{{stream}}` получает `true`. Редактор добавляет `Accept: text/event-stream`, если заголовок отсутствует. Подставь пути из событий своего API. Для OpenAI-совместимого потока обычно подходит такая настройка.

```json
{
  "format": "sse",
  "text": "choices[0].delta.content",
  "finish": "choices[0].finish_reason",
  "usage": "usage",
  "error": "error.message"
}
```

Для «Проверить вставленный SSE» скопируй события вместе с пустыми строками.

```text
data: {"choices":[{"delta":{"content":"При"}}]}

data: {"choices":[{"delta":{"content":"вет"}}]}

data: [DONE]

```

`text` должен извлекать очередной фрагмент. Приложение соединяет фрагменты по порядку. По умолчанию поток завершается по `data: [DONE]` или при закрытии соединения между событиями. Для другого маркера можно задать `done_data` или `done_event`. В чате текст виден по мере поступления, а OCR и перевод сопоставляют рамки после полного ответа.

## Отправка файлов через multipart/form-data

Укажи `Content-Type: multipart/form-data` в полном запросе. Границу частей приложение добавит само. Опиши форму JSON-объектом, где каждый ключ — имя поля из документации, а каждое значение — текст, число, JSON-структура или переменная. `{{files}}` указывается как целое значение поля. Пример с условным путём `process-file` показан ниже.

```http
POST process-file
Authorization: Bearer {{api_key}}
Content-Type: multipart/form-data

{
  "model": {{model}},
  "prompt": {{prompt}},
  "file": {{files}}
}
```

`{{prompt}}` берёт текст последнего сообщения пользователя. Можно использовать `{{messages}}` для истории, если сервис её принимает. При использовании `{{files}}` изображения уходят отдельными бинарными частями, а их base64 убирается из истории. Несколько вложений передаются отдельными частями с одним именем поля. Подбери имя поля, путь и правила ответа по документации сервиса. Сведения о ключе и каталог могут использовать multipart для текстовых полей, если так устроен их API.

Кнопка «Прикрепить файл» доступна в редакторе тестовой отправки и в чате, когда выбран шаблон с полем `{{files}}`. Вручную можно прикрепить файл до 10 МБ. В рабочем OCR приложение использует подготовленные изображения рамок. Перед отправкой вложений чат показывает адрес и просит подтверждение.

## Как проверить и где границы редактора

- В первой строке полного запроса указывай HTTP-метод и относительный путь. Редактор поддерживает `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`. Используй только метод, который документирует API для выбранной операции. Путь можно дополнить несекретными параметрами запроса. Абсолютный URL, смена хоста, параметры с ключом и фрагменты в пути не подходят. Заголовки пишутся по одному на строку. Для ключа в другом заголовке, например `X-API-Key`, используй `X-API-Key: {{api_key}}`, только если это требует поставщик.
- Пути разбора используют точки и числовые индексы, например `result.items[0].text`. `$` обозначает корень. Обычно успехом считается HTTP 2xx. Меняй правило `statuses` на массив кодов, например `[200, 201]`, только если это нужно по документации. Успешное тело должно быть JSON.
- Сначала открой «Предпросмотр» и проверь метод, URL и тело. Затем используй «Проверить вставленный JSON» с образцом ответа и правильным HTTP-статусом. Эта проверка выполняется локально. После этого отправь короткий тест с подтверждением. Для OCR начни с тестового чата и безобидной картинки. В рабочем сценарии отдельно проверь ответ с двумя рамками.
- HTTP 401 обычно требует проверки активного ключа и заголовка авторизации. При 403 проверь разрешения и ограничения сервиса. При 404 проверь базовый адрес, путь и идентификатор модели. При 429 проверь лимиты. При 2xx с ошибкой разбора сравни правила с фактическим JSON и форматом текста рамок.
- SSE применяется к чатовой операции и извлекает данные из JSON каждого события. Редактор работает с одним HTTP-запросом за раз. Для цепочек авторизации или произвольного преобразования массива `{{messages}}` проверь, предлагает ли поставщик совместимый API.
